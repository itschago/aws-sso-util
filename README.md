# aws-sso-util

> Utilities for making AWS IAM Identity Center easier to use from the command line.

`aws-sso-util` helps configure AWS profiles, authenticate with IAM Identity Center, work across multiple AWS accounts and permission sets, support AWS SDKs, and perform Identity Center administration tasks.

This fork adds support for the AWS CLI's modern **shared SSO session** configuration, including profiles generated by `configure populate` that work with:

```bash
aws sso login --sso-session <name>
```

> AWS IAM Identity Center was formerly AWS SSO. AWS configuration fields and APIs therefore continue to use `sso_*` names.

## Features

- Generate AWS profiles for all accessible accounts and permission sets
- Modern shared `[sso-session]` configuration
- Legacy AWS SSO profile compatibility
- Login and logout helpers
- Run commands as a specific account and permission set
- Open AWS Console sessions
- AWS SDK / `credential_process` support
- Identity Center diagnostics
- Administrator lookup and assignment utilities
- CloudFormation helpers
- Programmatic access through [`aws-sso-lib`](lib/README.md)

New to IAM Identity Center? Start with the [Identity Center primer](docs/primer.md).

## Installation

### pipx

`pipx` installs Python CLI applications in isolated environments.

On macOS:

```bash
brew install pipx
pipx ensurepath
```

Then install:

```bash
pipx install aws-sso-util
```

The AWS CLI v2 is also strongly recommended for native IAM Identity Center support.

Verify your installation:

```bash
aws-sso-util --help
```

## Quick start

Set your Identity Center portal and region:

```bash
export AWS_DEFAULT_SSO_START_URL="https://d-xxxxxxxxxx.awsapps.com/start"
export AWS_DEFAULT_SSO_REGION="us-east-2"
```

View the accounts and permission sets available to you:

```bash
aws-sso-util roles
```

Then generate profiles in `~/.aws/config`.

## Modern shared SSO sessions

Current AWS CLI versions support reusable authentication configuration through `[sso-session]` sections.

This fork adds `--sso-session` to `configure populate`:

```bash
aws-sso-util configure populate \
  --sso-session company \
  --region us-east-2 \
  --components account_name \
  --account-name-case lower
```

This creates one shared session:

```ini
[sso-session company]
sso_start_url = https://d-xxxxxxxxxx.awsapps.com/start
sso_region = us-east-2
sso_registration_scopes = sso:account:access
```

and generated profiles reference it:

```ini
[profile example-dev]
sso_account_name = example-dev
sso_account_id = 123456789012
sso_role_name = AdministratorAccess
region = us-east-2
sso_auto_populated = true
sso_session = company
```

Authenticate once:

```bash
aws sso login --sso-session company
```

Then use any profile associated with that session:

```bash
aws sts get-caller-identity --profile example-dev
```

All profiles referencing the shared session use the same Identity Center login.

### Shared-session behavior

When `--sso-session` is used:

- `sso_start_url` and `sso_region` are stored in `[sso-session NAME]`
- generated profiles contain `sso_session = NAME`
- `sso_registration_scopes = sso:account:access` is configured
- `credential_process` is omitted by default
- legacy per-profile SSO fields are removed when generated profiles are migrated

If required, `credential_process` can still be explicitly enabled:

```bash
aws-sso-util configure populate \
  --sso-session company \
  --credential-process \
  --region us-east-2
```

See [Configuration and profile generation](docs/configure.md) for all options.

## Legacy compatibility

Shared SSO sessions are opt-in. Omitting `--sso-session` preserves the existing per-profile format:

```bash
aws-sso-util configure populate \
  --region us-east-2 \
  --components account_name \
  --account-name-case lower
```

Example:

```ini
[profile example-dev]
sso_account_name = example-dev
sso_account_id = 123456789012
sso_role_name = AdministratorAccess
region = us-east-2
sso_auto_populated = true
sso_start_url = https://d-xxxxxxxxxx.awsapps.com/start
sso_region = us-east-2
credential_process = aws-sso-util credential-process --profile example-dev
```

Switching between modern and legacy generation cleans stale SSO configuration fields from generated profiles.

## Configuring AWS profiles

There are two primary configuration workflows.

Configure one profile:

```bash
aws-sso-util configure profile my-profile
```

Populate profiles for all accessible account, permission-set, and region combinations:

```bash
aws-sso-util configure populate --region us-east-2
```

Profile names are configurable. For lowercase AWS account names only:

```bash
aws-sso-util configure populate \
  --region us-east-2 \
  --components account_name \
  --account-name-case lower
```

Preview changes without modifying `~/.aws/config`:

```bash
aws-sso-util configure populate \
  --sso-session company \
  --region us-east-2 \
  --dry-run
```

See [`docs/configure.md`](docs/configure.md).

## Common commands

| Command | Purpose |
| --- | --- |
| `aws-sso-util roles` | List accessible accounts and permission sets |
| `aws-sso-util configure profile` | Configure one AWS profile |
| `aws-sso-util configure populate` | Generate profiles for accessible accounts and permission sets |
| `aws-sso-util login` | Authenticate with Identity Center |
| `aws-sso-util logout` | Clear Identity Center login state |
| `aws-sso-util run-as` | Run a command using a selected account and permission set |
| `aws-sso-util console` | Open an AWS Console session |
| `aws-sso-util check` | Diagnose configuration and access problems |
| `aws-sso-util credential-process` | Supply credentials to compatible SDKs |
| `aws-sso-util admin lookup` | Look up Identity Center identifiers |
| `aws-sso-util admin assignments` | Inspect Identity Center assignments |
| `aws-sso-util admin cfn` | CloudFormation assignment helpers |

Use `aws-sso-util <command> --help` for command-specific options.

```bash
aws sso login --sso-session company
```

The project also provides its own login helpers:

```bash
aws-sso-util login
aws-sso-util logout
```

## Using profiles

Select a profile directly:

```bash
aws sts get-caller-identity --profile example-dev
```

or set it for the current shell:

```bash
export AWS_PROFILE=example-dev
aws sts get-caller-identity
```

For one-off access without a preconfigured profile:

```bash
aws-sso-util run-as
```

See [`docs/run-as.md`](docs/run-as.md).

## AWS Console access

Open an AWS Console session for an account and permission set:

aws-sso-util console

## AWS SDK support

Modern AWS SDKs increasingly understand IAM Identity Center configuration directly.

For SDKs or applications requiring the AWS credential-process provider:

```bash
aws-sso-util credential-process --profile example-dev
```

Legacy profiles generated by `configure populate` enable `credential_process` by default.

Profiles generated with `--sso-session` do **not** enable it by default because current AWS CLI/SDK credential providers can consume shared SSO sessions directly. It can still be enabled with `--credential-process`.

Some SDKs may require:

```bash
export AWS_SDK_LOAD_CONFIG=1
```

See [`docs/credential-process.md`](docs/credential-process.md).

## Python library

The underlying Python library is [`aws-sso-lib`](lib/README.md), which provides programmatic Identity Center functionality such as interactive authentication, account and permission-set discovery, boto3 session creation, and lookup operations.

## Administrator tools

Identity Center administrators can look up identifiers and inspect assignments:

```bash

```

## Project history

`aws-sso-util` supersedes the original [`aws-sso-credential-process`](https://github.com/benkehoe/aws-sso-credential-process).

The project continues to use `sso_*` terminology because those names remain part of the AWS CLI and API interfaces even though the service is now called AWS IAM Identity Center.
